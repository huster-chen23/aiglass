# 5 分钟汇报稿

各位老师好，我的实验题目是《基于 UDP 的 AR/VR 画面实时串流通信仿真》。本实验主要研究计算机网络中的 UDP 如何应用于对实时性要求较高的 AR/VR 画面传输。

首先介绍实验背景。VR 渲染主机需要持续产生画面，头显需要尽快显示最新画面。如果使用传统可靠传输，丢包后等待重传会增加延迟；而 AR/VR 更关注实时性，所以我选择 UDP 作为主要传输协议。

系统分为服务端和客户端两部分。服务端模拟 VR 渲染主机，使用 Pillow 或 mss 捕获电脑屏幕，再用 OpenCV 压缩成 JPEG。JPEG 数据可能超过一个 UDP 数据报的安全大小，所以我设计了简单的应用层分片协议。每个数据包包含魔数、帧编号、总分片数、当前序号、负载长度和发送时间戳。客户端模拟 AR/VR 头显，收到分片后按照帧编号和序号进行重组，再用 OpenCV 解码显示。

这里需要强调，UDP 本身不保证顺序、不保证到达，也不负责重传。因此客户端设置了帧超时机制。如果一帧缺少任意分片，超过时间后就直接丢弃，而不是阻塞等待。这种设计能保证客户端尽量显示最新画面。

我进行了三组真实测试。第一组是 UDP 正常通信，测试约 5 秒，显示 99 帧，帧率为 19.64 fps，平均端到端时延为 3.95 ms，画面连续。第二组是 UDP 丢包实验，在客户端加入 50% 的随机丢包，显示帧数下降到 48 帧，帧率约 9.56 fps，说明 UDP 丢包会造成部分帧无法重组，画面出现跳帧，但后续帧仍然可以继续显示。第三组是 TCP 对照，显示 98 帧，帧率约 19.51 fps，说明在当前本机环境下 TCP 也能稳定传输，但它依靠重传保证完整性。

从结果来看，UDP 的优点是协议简单、延迟低、不会因为等待重传而阻塞后续视频帧；缺点是可能丢包、乱序和丢帧。TCP 的优点是数据可靠、有序，缺点是在高延迟或丢包网络中会产生队头阻塞，从而造成卡顿。对于 AR/VR 这类实时应用，旧画面即使完整到达也可能已经失去价值，因此实际系统通常更倾向于 UDP 或基于 UDP 的实时传输协议。

本项目还预留了 Mininet 实验。可以在 Ubuntu 中建立两个主机，用 netem 设置 20 ms 延迟和 5% 丢包，再分别运行 UDP 和 TCP，比较帧率、延迟和卡顿情况。

本实验的不足是目前采用整帧 JPEG，任意分片丢失都会导致整帧丢弃，TCP 模式也还没有加入统一时间戳。后续可以增加选择性重传、关键帧、前向纠错和更精确的 TCP 时延测量。
