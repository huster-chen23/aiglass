# AI 眼镜单人开发计划：软件仿真先行，硬件迁移在后

## 0. 结论

**一个人可以实现。** 前提是按"两阶段"走：

- **阶段一（纯软件仿真）**：眼镜的每个硬件都用 PC 上的软件替身代替，把所有软件问题（协议、延迟、识别、语音、集成）在这一阶段全部解决。
- **阶段二（硬件迁移）**：软件全链路稳定后，逐个把"软件替身"换成真硬件。**只换端点、不改协议**，迁移风险被降到最低。

你已经有最大的底牌：UDP 实时图传（server.py / protocol.py / client.py）已经跑通并有真实数据——这相当于五人分工里 A 板块的核心已完成。

## 1. 硬件 → 软件替身映射表（阶段一的灵魂）

| 真实硬件 | 软件替身（阶段一） | 迁移到硬件时只换这一层 |
|---|---|---|
| 眼镜摄像头 | PC 摄像头 / 屏幕捕获（已有） | USB/CSI 摄像头模组 |
| 眼镜显示屏 | OpenCV 窗口（已有 client.py） | 单目 OLED / 手机屏幕 |
| 麦克风 + 扬声器 | PC 麦克风 + 音箱 | MEMS 麦克风 + 骨传导耳机 |
| 镜腿按键 | 键盘按键（空格=拍摄，S=语音） | 物理按键 GPIO |
| 端侧 AI 芯片 | 同一台 PC 跑模型 / 云 API | 树莓派或边缘服务器 |
| 电池 / 功耗 | 跳过，仅记录数据 | 充电宝 + 电源管理 |

这张表本身就是迁移方案：阶段一保证接口不变，阶段二照表替换。

## 2. 阶段一：软件仿真（第 1–3 周，每周一个里程碑）

### 第 1 周：通信底座 + 仿真框架（你的舒适区）
- 摄像头捕获替换屏幕捕获（VideoCapture，接口不变）
- 定义控制通道：TCP + 4 种 JSON 消息（capture_req / ai_result / tts_req / heartbeat）
- 写一个 `simulator.py`：一键启动全部模块的 mock，谁没做完用假数据顶替
- **里程碑**：按空格 → 摄像头帧经 UDP 发出 → client 窗口显示，全程无线 <200ms

### 第 2 周：语音链路软件版
- 按键说话 → Whisper/FunASR 转文字 → 调 LLM API → TTS → 音箱播放
- 先用现成 API（OpenAI/讯飞/百度），不自己训模型
- **里程碑**：对麦克风说"我看到了什么"，2 秒内听到回答

### 第 3 周：视觉 AI 软件版 + 全链路打通
- YOLOv8 检测 + PaddleOCR 文字识别，跑在同一台 PC
- 串起全链路：**按 S → 抓拍 → 检测/OCR → 结果 JSON → TTS 播报**
- 同时 UDP 图传窗口持续显示第一视角 + 识别框叠加
- **里程碑**：纯软件的"AI 眼镜模拟器"完整演示一遍——这就是你阶段二的验收基准

## 3. 阶段二：硬件迁移（第 4–6 周，每周换一层）

### 第 4 周：主控与摄像头迁移
- 选型：主路线**安卓备用手机**（自带摄像头屏幕麦克风电池）；备路线树莓派 Zero 2W
- 把 A 模块的发送端跑在手机/树莓派上，PC 接收端不动——**协议零改动**
- **里程碑**：真摄像头画面无线传到接收端

### 第 5 周：语音与识别迁移 + 显示
- 麦克风/耳机接主控，PTT 物理按键（或屏幕按钮）替换键盘
- D 模块视算力决定：端侧跑轻量模型，或画面传到边缘 PC 推理后回传结果
- **里程碑**：脱 PC 的完整闭环（除显示外全部在眼镜端）

### 第 6 周：整机装配与验收
- 绑带/3D 打印镜架装配，续航实测，延迟/功耗数据表
- **里程碑**：戴上眼镜完成 5 分钟演示：按键→识别→播报 + 第一视角图传

## 4. 单人作战的风险与对策

| 风险 | 对策 |
|---|---|
| 时间不够（一人抵五人） | 范围收缩三原则：PTT 按键代替唤醒词、现成 API 代替自训模型、手机方案代替定制硬件 |
| 没人 review 代码 | 每 48h 用 mock 做集成烟测（保留五人计划里的机制），git 提交即自审 |
| 硬件调试卡死 | 阶段一的模拟器就是退路——任何硬件层失败，软件版仍可完整答辩 |
| 模型太慢 | 识别放边缘 PC，眼镜端只采集+显示，结果走 WiFi 回传 |

## 5. 为什么这个顺序是对的

阶段一结束时，你拥有：可演示的软件模拟器 + 全部接口协议 + 真实性能数据。阶段二的每个"换硬件"动作都是**可独立验证、可回退**的——亮不了屏就先不换屏，识别慢就先放边缘。软件问题全部前置解决后，硬件阶段不会再被软件 bug 混淆，这是产品公司"先仿真后上机"的标准做法。
