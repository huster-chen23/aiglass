## 三、问题清单 × 计网知识详解

### 问题 1：扫描不到 GT5 / 扫到也连不上

**现象**：三轮扫描 60+ 台设备，无 GT5 名称；匿名设备连不上（Device not found）。

**排查**：关手机蓝牙前后对比扫描；定向监听已知地址 30s×2；匿名强信号设备逐一连接探测。

**计网知识 ①：BLE GAP 角色 与 广播模型（GAP=通用访问规范）**
- Peripheral（外围）周期广播 → Central（中心）扫描 → 主动连接
- **可连接广播 vs 不可连接广播**：ADV_IND 可连；ADV_NONCONN_IND 不可连（只传数据不给连）
- 我们探测的匿名设备全是**不可连接广播**——所以"按地址连接"必然 Device not found

**计网知识 ②：RPA（可解析随机地址）与设备隐私**
- 绑定过的设备为防追踪使用**每 15 分钟轮换的随机地址**，广播不含明文名称
- 只有持有 **IRK（身份解析密钥）**的已绑定设备能识别"这是我的表"
- 实测印证：匿名设备地址每轮扫描都在变（04:B2→34:A0→32:DB…）
- 这就是"生态墙"第一层：**未绑定 = 广播不可见或不可解析**

**计网知识 ③：绑定（Bonding）与白名单直连**
- 绑定 = 交换密钥（LTK/IRK）存入双方
- 绑定态手表断连后**不发通用广播**，只发定向重连（只给已配对手机）或直接作为 Central 回连
- 定向监听 30s×2 零广播 = 实锤

### 问题 2：连上了却拿不到心率

**现象**：0x2A37 订阅成功但零通知；直接 Read 报 **Read Not Permitted**；4 分钟无推送。

**计网知识 ④：GATT 权限模型**
- 每个特征有属性位：Read / Write / WriteNoRsp / Notify / Indicate
- 0x2A37 只开放 Notify；Read 被厂商禁用（Read Not Permitted）
- 教训：**能订阅 ≠ 有数据**——数据流还需"测量会话"在设备侧激活

**计网知识 ⑤：推送（订阅）与拉取（轮询）**
- Notify = 设备侧有新数据主动推（省电、实时）
- 我们订阅了 CCCD（客户端配置描述符）成功，但上游没数据——
  推送通道畅通，源头关闭（对应课本"应用层推送 vs 轮询"取舍）

### 问题 3：华为"三重生态墙"（挑战分析的实证核心）

| 墙 | 表现 | 协议层根源 |
|---|---|---|
| 配对墙 | 解绑后必须扫码经运动健康重新绑定 | 私有配对协议 + 二维码凭证流程 |
| 广播墙 | 绑定态零广播，第三方不可见 | RPA + 定向广播（只给手机） |
| 测量墙 | 心率测量仅在运动健康会话激活时运行 | 会话有效性校验（FE86 私有通道为官方专用） |

**结论话术**：标准 GATT 通道在 GT5 上"形备而实亡"——服务表齐全（我们已 dump 全量服务），
但数据供给被厂商会话逻辑锁死。这决定了户外眼镜的选型原则：**只依赖标准协议保证可用的
数据源，厂商私有生态一律视为不可靠依赖**。

### 问题 4：GTP/1.0 协议开发与测试

**帧结构**：8B 头（meta0/meta1/ts/len）+ 0~200B 载荷 + 2B CRC-16/MODBUS

**计网知识 ⑥：应用层协议设计四要素**
- **编解码**：struct 大端定长 + 类型系统（type 6bit 支持未来扩展）
- **完整性**：CRC-16/MODBUS 覆盖全帧 → 篡改必检出（单测实证）
- **有序性**：seq 4bit 抗重放窗口 + frame 级缓存重组
- **前向兼容**：未知 type 丢弃不报错 —— 新传感器零成本接入

**计网知识 ⑦：纵深防御——为什么 CRC 之外还要长度校验**
- 攻击者篡改 len 后**重算合法 CRC** 可绕过单层校验（测试场景 2 实证）
- 长度与实际载荷一致性检查作为第二道独立防线 → 双重检出
- 对应课本：检错码只能检错，**协议状态机的一致性检查才是最终防线**

**计网知识 ⑧：增量节流（DeltaThrottle）**
- 规则：变化 ≥2 立即发；静止期 5s 兜底发一次
- 价值：遥测流 80% 是冗余，节流直接降低 BLE 占空比 → 手表省电
- 测试：虚拟时钟 7 断言全过（避免真实 sleep 的测试脆弱性——测试工程细节）

### 问题 5：adb / UI 自动化链路

**计网知识 ⑨：USB 调试授权模型**
- 首次连接 = RSA 密钥交换，手机端确认指纹（"一律允许"= 保存主机公钥）
- unauthorized 状态 = 通道建立但未授权

**计网知识 ⑩：uiautomator 控件树**
- 界面以无障碍节点树暴露，每个节点带 text/content-desc/bounds
- 精确点击 = 解析 XML 找文本节点 → 取 bounds 中心 → input tap
- 对比截屏目测：控件树是**结构化数据**，不依赖视觉对齐 → 规范可靠

### 问题 6：GB 意图接口的权限墙（意外收获）

**发现**：GB 的自动化接收器用 `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`
（**protection=signature**）保护——只有同签名应用能触发同步/导出意图，adb shell 也不行。

**计网知识 ⑪：Android 权限等级**
- normal（自动授予）/ dangerous（用户确认）/ **signature（同签名才授予）**
- GB 用 signature 级权限保护自动化接口 = 防恶意 App 滥用 → 也挡住了我们的 adb 触发
- 替代方案：UI 自动化（input tap）绕过权限层，直接操作界面
