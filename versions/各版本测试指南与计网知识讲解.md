## v1.1 手表互联（BLE 遥测）

### 在哪里测

**家里/宿舍就能测**——BLE 有效距离约 10 米，隔着一面墙也行。这是五个版本里唯一"足不出户"的。

### 测试步骤（手表充好电后）

1. 手表：设置 → 健康监测 → 开启"连续心率测量"
2. 眼镜端主机蓝牙打开，运行 `py ble_scan.py`
3. 在扫描表里找到 `HUAWEI WATCH GT5-XXXX`，记下地址
4. `py watch_hr.py --address 地址`
5. 进阶实验：戴着手表从 1m 走到 10m，记录扫描到的 RSSI 变化 → 画"距离-信号强度"曲线

### 计网知识：BLE 的世界（课本覆盖少，补充讲）

**GAP（通用访问规范）——设备怎么找到彼此**
- 手表 = **外围设备（Peripheral）**，广播自己的存在
- 你的电脑 = **中心设备（Central）**，扫描并主动发起连接
- 对照课本：这本质是"服务发现 + 客户/服务器"，只是发生在无线个域网

**GATT（通用属性规范）——数据怎么组织**
- 手表把自己暴露成一张"表格"：**服务（Service）→ 特征（Characteristic）→ 值**
- 心率服务 `0x180D` 里的心率测量特征 `0x2A37`，就是一行"只读 + 可推送"的数据
- 类比 HTTP：服务 ≈ 网站域名下的目录，特征 ≈ 具体资源 URL

**Notify vs 轮询（重要）**
- 笨办法：眼镜端每秒问一次"心率多少？"（轮询，poll）
- 聪明办法：**订阅 Notify**——手表心率一更新就主动推给你
- 对照课本：这就是应用层"推送 vs 拉取"的取舍；推送省电省流量，实时性更好

**连接参数（课本运输层的影子）**
- BLE 连接有"连接间隔"（7.5ms~4s），决定时延和功耗的平衡
- 间隔越短时延越低但越费电——手表选择"省电优先"，所以心率约 1 秒一跳

**CRC 双层校验的意义**
- BLE 链路层本身有 CRC24，我们的 GTP 又加了 CRC16——**端到端校验**原则：
  链路层只保护"这一跳"，应用层保护"从生成到消费"的全程语义

## v1.2 眼镜互联（ESP-NOW Mesh）

### 在哪里测

- **第一阶段**：小区花园/公园/操场——验证 50m、100m、200m 视距通信
- **第二阶段**：两栋楼之间——测试穿墙衰减（混凝土墙是 2.4GHz 杀手）
- 记录表格：距离 × 是否视距 × 成功率 × RSSI

### 计网知识

**非 IP 网络：不是所有网络都跑 IP**
课本以因特网为核心，容易造成"网络=IP"的误解。ESP-NOW 在 **MAC 层直接收发**，
没有 IP 地址、没有端口——通信靠 48 位 MAC 地址。这证明：IP 是因特网的选择，
不是网络的必然。（对照课本：局域网体系结构中 LLC/MAC 子层的独立性）

**洪泛路由（Flooding）+ TTL**
v1.2 的 Mesh 采用最简单的路由：收到不认识的包 → 复制发给所有邻居 → 直到 TTL 耗尽。
- 优点：不需要任何路由信息，零配置
- 缺点：重复包风暴
- 我们的对策：**去重表**（记录最近见过的包 ID，5 秒窗口）——本质与 TCP 序号去重同源
- 课本对应：距离向量/链路状态路由的"祖师爷"，网络层路由算法章节

**Ad-hoc / Mesh 网络**
无基础设施、节点对等、自组织——课本"无线网络"一节的概念在这里全部具象化：
拓扑动态变化、没有中心节点、每个节点既是主机又是路由器。

## v1.3 语音对讲与相互定位

### 在哪里测

- 语音：校园里两栋楼/两个校门之间（200m~1km 视距）
- 定位：让队友带着另一台原型走已知路线（用手机地图记真值），对比你的估距误差

### 计网知识：实时语音（课本"多媒体网络"章节的核心）

**时延预算分解（为什么 200ms 是及格线）**

```
采集 10ms + 编码 20ms + 打包 5ms + 传输 40ms + 抖动缓冲 60ms + 解码 20ms ≈ 155ms
```

超过 150ms 人耳就能感知"对讲机感"，超过 400ms 无法正常对话。

**抖动缓冲（Jitter Buffer）——课本 RTP 章节的关键机制**
- 网络时延有波动（抖动），包到达忽快忽慢
- 解法：收到包先放进缓冲区"等一等"，按固定节奏播放——**用时延换平滑**
- 缓冲太小：频繁断音；太大：对讲变对答（时延过大）
- 这就是"时延与质量权衡"的具象化

**RTP 思想在我们协议里的体现**
GTP/VOICE 分片自带 seq + ts（时间戳）：
- seq 用于**丢包检测**（序号跳了就是丢了）→ 丢弃/插值，不重传
- ts 用于**播放定时**（到点就播，不等迟到包）
课本 RTP/RTCP 一节的所有设计动机，与这里完全一致。

**RSSI 测距的物理原理**
自由空间路径损耗公式：距离翻倍，信号衰减 6dB。
用对数距离模型 `RSSI = -10n·log(d) + A` 反推距离——但多径反射让误差巨大
（±5~15m），所以叫"粗定位"。**这是物理层知识直接决定应用层精度的例子。**

**GPS 定位（v1.3 L3 层）**
4 颗以上卫星伪距测量 → 三球交汇 → 经纬度。两副眼镜的 GPS 坐标用
**Haversine 公式**算球面距离，配合磁力计算相对方位角——数学上就是立体几何。

## v1.4 LoRa 远距离链路

### 在哪里测

- 城市里只能测 1~2km（干扰大、遮挡多）
- **真正验收要去郊区/山顶**：秦岭实测前，先在环山路做预测试
- 记录：距离 × 扩频因子 SF × 丢包率

### 计网知识

**香农公式：带宽换可靠性的物理学**

```
C = B · log₂(1 + S/N)
```

LoRa 的思路反其道而行：**把速率压到极低（5kbps），换极强抗噪能力**。
速率越低，每个符号能量越高，同样的发射功率传得越远——这就是"距离与速率
不可兼得"的定量表达。（对照课本：信道容量章节）

**扩频（Chirp Spread Spectrum）**
LoRa 用线性调频扩频：把一个比特摊在一段扫频信号上，噪声只干扰一小段也能解出。
扩频因子 SF7→SF12：SF 越大速率越低、传得越远——**每个 SF 是速率/距离的天平刻度**。

**法规：占空比（Duty Cycle）**
433MHz 公共频段有发射时长限制（如 10%），所以 LoRa 只能发"信标+短文本"，
不能跑语音——**技术之外还有监管约束**，工程方案必须考虑。

**星型 vs 网状**
LoRaWAN 经典架构是星型（所有节点直达网关）——与 v1.2 Mesh 的对偶：
覆盖换复杂度。两种架构在课程设计里的取舍是绝佳答辩题。

## v1.5 有网增强（天气/地图/GLM 融合）

### 在哪里测

- 家里（有网环境）：API 调试、瓦片下载
- 户外验证：出门前下载离线瓦片 → 山里看 HUD 是否正常显示航点

### 计网知识

**REST API 调用（应用层）**
天气 API = HTTPS GET + JSON 响应。重点：**超时与重试策略**——户外网络时好时坏，
API 必须有 3s 超时 + 本地缓存兜底（"最后一次成功数据"比"白屏"有价值）。

**瓦片地图原理（内容分发的端侧缩影）**
- 世界地图被切成 2^z × 2^z 张 256×256 PNG（z=缩放级别）
- 加载某区域 = 按坐标取若干瓦片 → **本地缓存**
- 这就是 CDN 内容分发的最小模型：就近取、存复用
- 离线地图 = 出门前"预取"瓦片——**预取（prefetch）是应对弱网的标准武器**

**上下文注入（GLM 融合）**
把心率/海拔/天气/队友位置组织成结构化提示词 → GLM 输出决策建议。
网络视角：这些数据来自 4 条不同链路（BLE/ESP-NOW/LoRa/HTTPS）——
**多网融合的会话层雏形**。

## v2.0 硬件一体化

### 在哪里测

- 实验室：功能回归（所有 v1.x 功能在嵌入式上重新验收）
- 户外：一次 2 小时徒步（记录续航、断连次数、定位漂移）

### 计网知识

**嵌入式网络栈的裁剪**
主控资源有限 → 网络栈逐层瘦身：去 IPv6 扩展头、精简 TCP（或干脆用 UDP+应用层）、
静态内存代替动态分配。对照课本"协议栈分层"——每一层都可以按需裁剪。

**功耗管理（无线设备的命门）**
- BLE 连接参数协商：拉长连接间隔省电
- 无线电"睡眠-唤醒"占空比调度
- 测量方法：电流表串联实测均值电流 → 续航 = 电池容量/均值电流
（这是物理题也是网络题：通信策略直接决定续航）
